# Doro Creator Toolkit

Agent-first local application. Read README.md before operating. UI, CLI and MCP must use shared validated operations. Do not bypass revision checks or persist raw project edits. Keep credentials and internal strategy out of source. Run tests and build after changes. Use headless browser verification. No Doro upload, scheduling or publishing without explicit action approval. Render through the pinned local HyperFrames adapter. Public sample content needs editorial and rendered review before release.

For installation and content workflows, read skills/carousel-creator/SKILL.md. Discover live tool schemas rather than guessing arguments. Export the saved revision, poll to completion, inspect outputs and report limitations accurately. Advanced gallery examples are not selectable editable-slide treatments.


## Ownership

Carousel-specific changes belong in tools/carousel, including its UI, tests and examples. Keep CLI/server/MCP entry points and genuinely shared utilities in packages. Keep agent guidance in skills. Read docs/architecture.md before adding a capability; add only real implementations, not empty future folders. Run npm test and npm run build from the repository root. For a cross-layer carousel change, run npx tsx tools/carousel/tests/local-journey.ts in isolated storage. Preserve saved data locations and public command compatibility during reorganizations.
